# Tessera

System stylu i komponentów React (`@mattymroz/tessera`) dla aplikacji właściciela: konsument składa interfejs z części Tessery i nie pisze własnych stylów. Repo to bun workspace z jedną paczką i stroną dokumentacji, która jest zarazem laboratorium.

## Bramki jakości

```sh
bun run check          # typecheck (TS 7) → build (tsdown, potem next build) → eslint → bunx vitest run --maxWorkers=6 → Playwright laboratorium (test:browser)
bun run dev            # tsdown --watch paczki i next dev laboratorium równolegle, jeden link
bun run perf           # build, potem T1–T5, N8 i S-A na /stress (Chromium, CPU 4x, mediana z 5, ok. 2,5 min); poza check i CI
bun run perf:save      # to samo i zapis apps/docs/perf/last.json jako nowego punktu odniesienia
                       # perf oblewa, gdy pomiar jest ponad 2× gorszy od last.json (ten sam Chromium i CPU); uruchom przed i po każdej zmianie ruchu, przepisu albo silnika
SKIP=no-commit-to-branch prek run --all-files   # hooki commitów na całym drzewie (na main bez SKIP zawsze czerwone)
```

- IMPORTANT: testy tylko `bunx vitest run`, NIGDY `bun run test`.
- Playwright tylko headless, 19 workerów (20 rdzeni logicznych bez jednego; decyzja właściciela 03.11) i jedno powtórzenie testu, który padł pod obciążeniem (`playwright.config.ts`); test, który pada dwa razy, to błąd. Pliki mierzące czas i klatki (`TIMED`: budżety, menu, skala, Switch, dialog potwierdzenia, oraz `jump.spec.ts`) biegną po reszcie w projektach `*-timed` z jednym workerem, bo pod obciążeniem padają także w powtórce. WebKit ma 6 workerów: na Windows liczy animacje na głównym wątku, więc przy 19 testy klatek (tooltip, popup, symetria) padają. Gdy naraz idzie kilka ciężkich rzeczy, `--workers=6`.
- Hook pre-push uruchamia cztery pierwsze kroki `bun run check` (typecheck, build, lint, vitest), w tej samej kolejności: build przed lintem, bo wtyczka ESLint konsumenta jest czytana z `dist`. Testy przeglądarkowe laboratorium biegną w CI (repo publiczne, minuty GitHuba za darmo; decyzja właściciela 03.11); merge do `main` tylko przy zielonym CI. Instalacja po klonie: `git config --local core.autocrlf false`, `prek install`, a w `apps/docs` `bunx playwright install chromium webkit` (bez przeglądarek `check` pada na ostatnim kroku; CI instaluje je sam).

## Twarde reguły

- IMPORTANT: każda zmiana jest globalna: idzie do silnika albo przepisu i dziedziczą ją wszystkie elementy. Nigdy nie stylujesz jednego elementu osobno.
- IMPORTANT: żadnej zmiany bez researchu, jak zrobili to najlepsi.
- IMPORTANT: zaplanuj → wykonaj → oceń.
- Materiały źródłowe: `tmp/index.md`.
- IMPORTANT: commit i push tylko na wyraźne słowo właściciela. Subagenci nie wykonują żadnych komend git.
- `main` dostaje tylko squash merge PR (hook `no-commit-to-branch`). Praca na branchach w worktree `.worktrees/<nazwa>`. Tytuł PR = nagłówek commita, opis PR = streszczenie (ustawienie repo: domyślna wiadomość squash = tytuł i opis PR).
- Commit: `type(scope): description`, scope obowiązkowy z zamkniętej listy `--scopes` w `.pre-commit-config.yaml`; pod nagłówkiem streszczenie. Kontrole nie biegną przy commicie: szybkie idą w hooku pre-push, przeglądarkowe w CI (decyzja właściciela 03.11). Zero śladów AI w commitach i PR. Strażnicy hooków w `.hooks/` to kopie z presetu `agents` (`presets/hooks/assets/hooks/`); nie edytuj ich tutaj, aktualizacja to ponowne skopiowanie.
- Kod etapu nie powstaje bez kontraktu w `docs/plans/` zaakceptowanego przez właściciela.
- Status przed oceną właściciela na żywo, w kompozycji, to najwyżej „gotowe do oceny”.
- Zero legacy: bez warstw zgodności z v1/v2, aliasów starych nazw i słowa `legacy` w kodzie. Kod przenoszony z v2 przepisuj na model v3.
- Zero pustych folderów i pakietów „na zapas”: folder powstaje z pierwszym plikiem.
- IMPORTANT: zero komentarzy w kodzie (TS, TSX, CSS, skrypty, testy, fixture), także WHY; kod tłumaczy się nazwami stałych, funkcji i plików. Powód, którego nie da się wyrazić nazwą, trafia do `docs/` (decyzja, plan) albo do opisu commita.
- Kod, nazwy, git i tekst UI po angielsku; dokumenty w `docs/` i ten plik po polsku.
- Zależności tylko przez bun: `bun add` w katalogu członka workspace, wspólne wersje przez `catalog:` w korzeniowym `package.json`.
- YOU MUST edytować pliki tylko narzędziami Edit/Write. Nigdy PowerShell (`Set-Content`, `Out-File`) ani skrypty: PS 5.1 robi mojibake z polskich znaków. Pliki są UTF-8 + LF (`.gitattributes`).

## Model warstw

Trzy piętra: **silniki** → **przepisy** → **komponenty**; motyw to tylko zestaw wyborów silników. Warstwy w `packages/tessera/src/` powstają z pierwszym plikiem:

- `engines/<silnik>.css` (jeden plik na silnik; reguły i zmienne w `@layer theme`, a `@keyframes`, `@property` i `@font-face` na szczycie pliku poza warstwą, bo tak wymusza strażnik): wejścia (`data-*`, `--ts-in-<silnik>-*`) → wyjścia `--ts-<silnik>-<rola>`. Publiczne API to wyjścia silników i klucze rejestru wartości instancji `--ts-i-*`. Silnik deklaruje tylko własne wyjścia, wejścia i prywatne `--_ts-<silnik>-*` i czyta tylko silniki, od których zależy. Rejestr `@property --ts-i-*` (`inherits: false`) żyje tylko w `size.css`, a jego klucze to dokładnie `INSTANCE_KEYS` z `lib/instance.ts`. `@keyframes` są tylko w `motion.css`: wyłącznie `ts-spin`, `ts-sweep`, `ts-pulse`, z samymi `transform`/`translate`/`rotate`/`scale`/`opacity`. Wyjątek: `color.css` jest generowany (`bun run generate:colors` w paczce, dane w `scripts/palette.ts`), nie edytuj go ręcznie.
- `recipes/<przepis>.css` (w `@layer components`, sześć przepisów: `control`, `surface`, `row`, `indicator`, `focus`, `text`): wartości wyłącznie z wyjść silników, kluczy rejestru `--ts-i-*`, własnych `--_*`, zmiennych dostawcy z listy `VENDOR_VARIABLES` i liczb `0`, `1`, `-1`, `100%`; funkcje tylko `calc`, `min`, `max`, `clamp` i `color-mix(in oklab, …)`; nigdy inne liczby ani kolory, prefiksy producenta ani arytmetyka na `--_*` zbudowanej z literału. At-rule tylko `@media (hover: hover)`, `@media (forced-colors: active)` (słowa kolorów systemowych, np. `Highlight`, `ButtonText`, wyłącznie w tym bloku), `@container` z progiem z `CONTAINER_WIDTHS` i `@supports (overflow-clip-margin: border-box)` tylko w `control` i tylko z `overflow` i `overflow-clip-margin` (przycięcie pętli do obrysu, powód w `docs/structure.md`; blok bez tych właściwości oblewa); `@starting-style` zabroniony, także dla toastu: jego wejście (E3) idzie przez atrybut `data-starting-style` Base UI i zwykłe `transition`. Ton (`data-tone`) jest osią obok wariantu, nie nowym wariantem; powierzchnia z tonem bez obrysu. Selektor celuje w element przepisu, jego `[data-slot]` albo pseudo-element (bez `~`, `+`, `:root`, `html`, `body`); wyjątki z powodem w `docs/structure.md`.
- `components/<rodzina>/<nazwa>.tsx` (+ opcjonalnie `<nazwa>.css` importowany tylko z `tessera.css`): CSS tylko z rozmieszczeniem części (`display`, `gap`, wyrównania, `flex*`, `order`, kolumny i wiersze siatki) i wartościami z tokenów, tylko w zakresie `[data-component='<nazwa>']` i jego części; jedyne at-rule to `@container` z progiem z `CONTAINER_WIDTHS` (`test/guards/css-layers.ts`) i samymi właściwościami układu. Rozmiar, pozycja, kolor, promień, cień, ruch, liczby poza `-1`/`0`/`1` i własny `:focus-visible` należą do przepisów i silników.
- TSX komponentu: bez `className` i budowania klas; `style` tylko jako obiekt literalny z kluczami rejestru `--ts-i-*` (wartość instancji, np. postęp); wartość z pomiaru DOM zapisuje `writeInstance` tylko w plikach z listy pomiaru (Q7: `lib/bar-overflow.ts`, `lib/indicator.ts`, `lib/motion.ts`, `lib/popup-flight.ts`, `lib/press.ts`, `lib/select-align.ts`, `lib/submenu-pointer.ts`, `lib/title-when-cut.ts`, `lib/tooltip.ts`; pomiar to też odczyt `scrollWidth`, `clientWidth`, `scrollHeight`, `clientHeight`, `scrollTop`, `scrollLeft`). Bez literałów liczbowych poza `0`, `1`, `-1` (także w stałych; czasy zachowania to nazwane stałe w `lib/`) i bez atrybutów wyglądu SVG (`strokeWidth` i inne spoza białej listy w `docs/structure.md`). Glify komponentów i ikony laboratorium pochodzą z lucide: domyślny import modułu jednej ikony (`import Check from 'lucide-react/icons/check'`, w paczce pilnuje `test/package/package.test.ts`), bez propsów wyglądu; rozmiar daje slot, grubość kreski przepis (`docs/decisions/e3-icons.md`). Pozycje typów (`level: 1 | 2 | 3 | 4`) są dozwolone.
- Komponent nie zawiera tekstu UI w żadnym języku: każda etykieta (np. `cancelLabel` w `confirm()`) to wymagany prop bez wartości domyślnej; `onClick` tylko na elemencie interaktywnym albo kontenerze widżetu złożonego z rolą (`radiogroup`). Pilnuje `test/guards/component-source.ts` (wywołany z `contracts.test.ts`).
- Zmiana wyglądu jednego elementu = wariant przepisu, nie token komponentu. Poprawki wyglądu idą do silników i przepisów, nie do komponentów.
- Pilnuje tego `packages/tessera/test/guards/css-layers.ts` (biała lista per warstwa, fixture `good/` i `bad/`), `contracts.test.ts` i blok `tessera/components` w `eslint.config.js` (lokalna reguła repo `tessera-source/component-appearance` z `test/guards/component-appearance.ts`, ładowana ze źródła, poza publiczną wtyczką); propsy elementu i części Base UI idą przez jeden typ `Unstyled` (`lib/unstyled.ts`), który zdejmuje `className`, `style` i `render`. Nowa reguła dostaje strażnika od razu: biała lista plus jawne wyjątki z powodem, nigdy kopia listy tokenów.

## Wydajność i ruch

Priorytet nr 1 to wydajność. Pełna lista wymagań i budżetów: `docs/specification.md`, sekcja „Wymagania jakościowe”.

- IMPORTANT (reguła właściciela 09.11): wygląd idzie razem z szybkością. Każdy element piszesz od razu tak, żeby był najszybszy, a nie najpierw ładny i potem optymalizowany:

  - w klatce ruchu zero pracy głównego wątku: ruch tylko na kompozytorze, bez animowanego układu, malowania i filtrów poza nazwanym wyjątkiem z pomiarem kosztu;
  - JS tylko raz na zmianę stanu, nigdy w klatce; w jednym przebiegu najpierw wszystkie odczyty DOM, potem wszystkie zapisy, bez przeplatania wymuszonych przeliczeń;
  - w spoczynku żadnej warstwy kompozytora, żadnego nasłuchu na dokumencie per element, żadnego atrybutu na `<html>` zmienianego przy interakcji;
  - dowód przed „gotowe do oceny”: ślad Chromium przy CPU ×4 dla interakcji elementu porównany ze zwykłym przyciskiem w tym samym przebiegu i `bun run perf` przed i po zmianie; regres względem stanu sprzed zmiany to stop i naprawa przed oddaniem.

- Ruch tylko `transform`/`translate`/`scale`/`rotate`/`opacity`. Każdy inny przypadek to nazwany wyjątek z powodem w jednym pliku. Zmiana rozmiaru dzieje się w jednej klatce, nigdy w ruchu.

- Jedna skala czasów: każdy ruch bierze czas i krzywą z kategorii silnika `motion` (wyjście hovera `hover-out` 150 ms tylko na wyjściu, pogoń `follow` 100 ms, wybór `choice` 220 ms z odbiciem, scena `scene` 250 ms, wciśnięcie 50 / 224 ms), nigdy własną liczbę elementu; menu, lista rozwijana, podmenu i popover otwierają się i zamykają bez przejścia, wiersz listy bez poświaty. Tooltip (decyzja właściciela 08.11, `docs/decisions/e3-choices.md`) wchodzi krycie `hover-out` + wjazd `--ts-motion-appear-shift` (4 px) od wyzwalacza w `follow`, wychodzi kryciem w 50 ms, kolejny w oknie ciepła 400 ms bez wejścia; w pasku jeden dymek jedzie i zmienia szerokość w `follow` z krzywą pigułki hovera (`--ts-motion-ease-hover`), tekst przenika się z rozmyciem i w każdej klatce ma szerokość dymka (ściśnięcie `scale` ≤ 1 z klucza `--ts-i-tip-squish`); kliknięcie, Enter i Spacja zamykają tooltip (decyzja właściciela 08.11). Oś `data-motion` ma `on` i `off`; `prefers-reduced-motion` zostawia gaśnięcie koloru i scenę, zdejmuje skalę i ruch pigułek. Wyjątki poza kompozytorem, każdy z wyjątkiem wartości w `test/guards/css-layers.ts`: (B2) przejście `background-color` płytki `::before` kontrolki przy wyjściu hovera (`recipes/control.css`, pomiar w `budgets.spec.ts`); `width` dymka tooltipa i `filter` jego tekstu w przejściu między przyciskami paska (`recipes/surface.css`; przelicza układ tylko dymka w warstwie wierzchniej). Trigger listy rozwijanej (`aria-haspopup='listbox'`) i segment `joined` nie skalują się wcale; opcja toru i wiersz menu nie mają kroku wciśnięcia. Zmiana osi motywu (`applyChoices`) stawia na `<html>` wejście silnika `data-motion-hold`, które zeruje czasy przejść do drugiej klatki po zmianie, żeby przełączenie motywu nie animowało płytek (test w `lab.spec.ts`); czasy pigułki (`choice`, `follow`) zostają, bo pigułka grupy, która zmieniła motyw, ma jechać (`toggle-group.spec.ts`, „slides the pill of a group while the document holds the plates of a theme change”). Strażnik czasów: `interaction.spec.ts` (computed style kontra silnik w trzech trybach) i `contracts.test.ts`.

- IMPORTANT (reguła właściciela, błąd powtarzany wielokrotnie): nigdy nie transformuj (`scale`, `translate`, `rotate`) elementu, do którego przypięty jest inny element — kotwicy popupu, menu, tooltipa, podmenu, pigułki — ani przodka takiej kotwicy czy przypiętego elementu. Kotwicę przepis `control` rozpoznaje po atrybutach, które stawia Base UI (`aria-haspopup`, `aria-expanded`, `data-popup-open`, `data-tooltip-trigger`): kotwica stoi, a wciśnięcie dostają tylko jej sloty `icon` i `label` i płytka `::before`, więc popup nie skacze, nie mruga i nie skaluje się razem z triggerem. Zwykły przycisk (grupa „skala”) wciska się cały: płytka, tekst i ikony (`docs/decisions/e3-motion.md`, TE). Grupa `joined` z kotwicą wśród segmentów nie dostaje spoczynkowej skali grupy. Strażniki: `button.spec.ts` „presses the whole control of every button and only the parts and the plate of an anchor…” (`data-pressing` na każdej kontrolce trzech stron, kotwica i jej przodkowie bez `scale` i `transform`) i „keeps a popup and its trigger still…” (menu, menu szerokości triggera, popover, tooltip, podmenu: prostokąty co 8 ms przed, w trakcie i po wciśnięciu) oraz `interaction.spec.ts` (grupa wciśnięcia każdego elementu interaktywnego).

- Wciśnięcie (TE, decyzja właściciela 02.11): grupa „skala” ma w spoczynku `scale: var(--ts-motion-press-rest)` (0,99999, transformacja bez warstwy, więc spoczynek przyciąga do siatki pikseli tak samo jak ruch), a przy `[data-pressing]` `will-change: scale` i przejście do `--ts-motion-press-scale`; czasy i krzywe tylko z wyjść silnika `motion`. `data-pressing` stawia jeden nasłuch na dokumencie (`lib/press.ts`, `watchPresses` w refie kontrolki): lewy przycisk i dotyk, Space trzyma do `keyup`, Enter błyska na `--ts-motion-press-hold`, zjazd z prostokąta z chwili `pointerdown` puszcza. Strażnik skoku: `jump.spec.ts` (obraz spoczynku = obraz z warstwą ruchu przy prawdziwym `--force-device-scale-factor` 1 / 1,25 / 1,5 / 2, tylko Chromium).

- Nie udawaj zmiany rozmiaru kopiami DOM ani kawałkami wskaźnika lub popupu: ta droga została sprawdzona i odrzucona.

- Zero runtime CSS-in-JS. Wariant i motyw to atrybuty `data-*` + CSS, nie kontekst React.

- Kształt i rozmiar nie przechodzą przez JS (bez `ResizeObserver` + `getComputedStyle` + `setProperty`); pomiar DOM tylko tam, gdzie wymaga go zachowanie, w plikach z nazwanej listy.

## Mapa kodu

- `packages/tessera/`: jedyna paczka. `exports` per ścieżka (bez zbiorczego `.`): `dist/` dla każdego konsumenta, także laboratorium; warunek `source` → `src/` czyta tylko TypeScript (`customConditions`), bo Turbopack nie obsługuje własnych warunków (`docs/decisions/e1-source-condition.md`); `sideEffects` tylko CSS.
  - `src/styles/tessera.css`: jedyne miejsce kolejności `@layer`, importy fontów (`wght.css`) i plików silników, przepisów i komponentów (bez `layer()`: każdy plik sam trzyma swoją warstwę). Drugie wejście, `tailwind.css`, to wyłącznie `@theme inline` z `var(--ts-*)`.
  - `scripts/`: generator koloru; poza `src`, więc nie trafia do `dist`.
  - `src/eslint/`: reguły konsumenta, każda z jedną semantyką, bez trybów; `index.ts` eksportuje wtyczkę `@mattymroz/tessera/eslint` z `configs.recommended`, testy w `rules.test.ts`. Strażnik źródeł komponentów nie należy do wtyczki: to lokalna reguła repo w `test/guards/component-appearance.ts`.
  - `src/lib/`: wspólne zachowanie bez wyglądu, plik = jedna odpowiedzialność (np. `motion.ts`: odczyt silnika ruchu; `flight.ts`: czysta fizyka lotu; `indicator.ts`: tylko sterownik DOM pigułki i `useIndicator`; `focus-field.ts`: wciśnięcie ikony albo paddingu `Input` i `Textarea` i etykieta bez kontrolki fokusują pole; `slot.ts`: gospodarz i części komponentu złożonego, `usePart` rzuca błąd dla części poza gospodarzem albo w innej części, `useHost` ten sam błąd dla części poza kontekstem gospodarza, `useSlotOrder` dla slotu poza kolejnością; `press.ts`: jeden nasłuch wciśnięcia na dokument, instalowany leniwie przez `watchPresses` z licznikiem odwołań; model i powody w `docs/decisions/e3-slots.md`; `unstyled.ts`: jeden typ propsów bez wyglądu z zewnątrz).
  - `src/components/`: rodziny widżetów (lista w `docs/structure.md`). `dialog/alert-dialog.tsx` daje `confirm()` przez jeden `ConfirmHost`, który aplikacja montuje raz przy korzeniu (laboratorium: `apps/docs/app/layout.tsx`); bez hosta `confirm()` od razu zwraca `false`.
  - `test/guards/`: strażnik warstw CSS (`css-layers.ts`, z progami `CONTAINER_WIDTHS`), lokalna reguła ESLint źródeł komponentów (`component-appearance.ts`, test `component-appearance.test.ts`) i kontrakty źródeł (`contracts.test.ts`: silniki = graf, pomiar DOM tylko w nazwanych plikach, kolor = generator, osie motywu ↔ reguły silników w obu kierunkach, komponent = `docs/<nazwa>.md` + ≥ 2 strony laboratorium (bez `/stress` i `/proposals`), propsy elementu i części Base UI przez `Unstyled`, kontekst gospodarza = `null` + `useHost` (`hostContextProblems` w `component-source.ts`), lint laboratorium = dokładna lista bloków: jeden wyjątek wyłączający regułę (D23, `/foundation`) i jeden konfigurujący regułę z powodem (`lab/first-frame-probe`)).
  - `src/eslint/layout.ts`: dane układu w jednym miejscu: lista właściwości (`COMPONENT_LAYOUT` dla strażnika CSS, `APP_LAYOUT` dla reguł konsumenta) i wzorce klas układu (`LAYOUT_CLASSES`, `LAYOUT_FAMILIES`), które `style-policy.ts` składa w regułę.
  - `test/fixtures/`: wspólne dane testów TS (`motion.ts`: `MOTION`, czasy kategorii silnika `motion` w zwykłym trybie).
  - `test/package/`: kontrakt zbudowanej paczki (exports, `'use client'`, brak efektów ubocznych, React Compiler, ikony lucide ikona po ikonie) i budżety `dist`: B6 (`minifySync` z `rolldown/utils` plik po pliku, gzip poziomu 9 komponentu z prywatnymi `lib/` ≤ 3072 B, CSS ≤ 56 494 B) i B8. Nie `test/dist/`: preset `.gitignore` ignoruje każdy katalog `dist/`.

## Pułapki

- Testy `test/package/` i laboratorium czytają `packages/tessera/dist/`: bez świeżego `bun run build` oblewają albo widzą stary build. `bun run check` buduje przed testami. Na świeżym klonie przed pierwszym `bun run dev` zrób `bun run build`, bo `--parallel` nie czeka, aż tsdown skończy.
- Typecheck idzie przez TypeScript 7 (`typescript7` = `npm:typescript@^7`, skrypt `typecheck` każdego członka). TypeScript 6 zostaje tylko jako peer `typescript-eslint`; nie zamieniaj ich.
- `git worktree remove` (z `--force` i bez) wchodzi na Windows w junctiony i kasuje ich cel. Junctiony robią `link:` u konsumenta (paczka Tessery w worktree MangaShift) i linki skilli. Przed usunięciem worktree albo katalogu najpierw zdejmij linki (`rmdir` na junction), potem `git worktree remove` bez `--force`. Globalny `guard.sh` odmawia usunięcia, dopóki linki istnieją.
- W worktree nie synchronizuj skilli: `@core` jest globalny.
- Hook `mdformat` przy commicie przepisuje Markdown: po `git add -A` puść `prek run` i dodaj zmiany jeszcze raz, aż drzewo przestanie się zmieniać, inaczej commit pada.
- Osie `mode` i `accent` działają tylko na `<html>`: reguły koloru wymagają obu atrybutów na jednym elemencie, więc `data-mode` albo `data-accent` na poddrzewie daje złe kolory. Motyw zapisuje je wyłącznie na korzeniu.
- `test:browser` stawia serwer na porcie `LAB_PORT` (domyślnie 4310) i poza CI używa serwera, który już tam działa. Dwa worktree naraz: osobny `LAB_PORT` dla każdego, inaczej testy jednego trafią na build drugiego.
- Bok popupu i dialogu o 10 px większy niż góra → rynny `scrollbar-gutter` klasycznego paska Windows; popup i dialog przewijają się bez paska i rynien → strażnik `symmetry.spec.ts` i `edges.spec.ts` (rynny = 0).
- Bok powierzchni równy górze mimo dużego promienia, treść wjeżdża w łuk → odstęp bez ¼ promienia; `--ts-shape-inset` = odstęp + obrys + ¼ okrągłego promienia → strażnik `symmetry.spec.ts`.
- Góra powierzchni o ok. 4 px większa niż bok przy tekście na krawędzi → interlinia nad pierwszą i pod ostatnią linią; przycięcie linii na krawędzi w przepisie `text` → strażnik `symmetry.spec.ts`.
- Tekst kontrolki o 0,5–1 px za wysoko albo za nisko (xs, md, lg, xl) → przeglądarka zaokrągla ascent i descent fontu, więc środek linii ≠ środek wersalików; tekst kontrolki i wiersza zawsze w `[data-slot='label']`, przycięty z `--ts-size-cap-pad` → strażnik `symmetry.spec.ts`. W natywnym `<input>` i `<textarea>` tekstu nie da się przyciąć: zostaje do 0,75 px (`FONT_ROUNDING`).
- Kontrolki pól w karcie w różnych miejscach → każda `Field` miała własną siatkę; pola dzielą kolumny karty (`subgrid`) → strażnik `symmetry.spec.ts`.
- Przycisk „×” w rogu niekoncentryczny albo tytuł pod nim → slot `close` przepisu `surface` (offset `--ts-shape-inset`) i reguła tytułu w `text` → strażnik `symmetry.spec.ts`.
- „×” i akcja nagłówka karty niekoncentryczne przy `sm` i `xs` (promień 6,9 px zamiast 9,9 px), choć przy `lg` dobrze → promień kontrolki w powierzchni to `min(własny, inner)`, a mała kontrolka ma własny mniejszy; slot `close` i akcja nagłówka biorą `--ts-shape-concentric` → strażnik `symmetry.spec.ts` (kompozycja: rogi `none`/`md`/`full` × rozmiary `sm`/`lg`).
- Karta, dialog albo grupa z długim URL-em, ścieżką lub etykietą wychodzi poza rodzica (karta 120 px rozpychana do 837 px) → najmniejsza szerokość kontrolki to cała etykieta, slot z kontrolkami w siatce dostaje ją jako automatyczne minimum, a `break-word` nie zmniejsza min-content tekstu; `max-inline-size: 100%` w `control`, `min-inline-size: 0` slotów `actions` i akcji nagłówka, `overflow-wrap: anywhere` w `text` i `surface` → strażnik `edges.spec.ts` (sekcja Overflow, `overflowProblems`, `windowProblems`).
- Karta albo pole w wąskiej ramce łamie długi tekst po jednej literze (kolumna tytułu 13,5 px, etykiety 11,5 px), także karta 500 px z długą akcją → w siatce `1fr auto` kolumna `auto` rośnie do max-content akcji przed rozdaniem `1fr`, a minimum `1fr` to jedna litera (`overflow-wrap: anywhere`); próg `@container` czyta stronę, nie kartę, więc o tym nie decyduje. Nagłówek karty to zawijany rząd flex, tytuł z podstawą i minimum `min(--ts-type-measure-min, 100%)` (12 ch), akcja spada pod tytuł, gdy obok się nie mieści; pole i karta z polami (`subgrid`) mają kolumny `auto auto` z `justify-content: space-between` → strażniki `edges.spec.ts` (`letterBreaks`: ramki Overflow i każda strona laboratorium przy 320–1920) i `card.spec.ts` („keeps the title of every card header at least the least measure wide…”).
- Tooltip skakał w pasku (szerokość +55 px w jednej klatce, tekst zmieniany w pierwszej klatce lotu, prędkość od nowa przy każdej zmianie celu), bo pozycję liczył pozycjoner Base UI, a lot szedł osobną animacją `transform` → własny tooltip (`lib/tooltip.ts`): JS liczy pozycję i szerokość raz na zmianę celu i zapisuje wartości instancji `--ts-i-tip-*`, ruch robią przejścia CSS (`translate`, `width`, przejmowane z bieżącej wartości), dymek w warstwie wierzchniej (`popover="manual"`) → strażnik `tooltip.spec.ts` (`docs/decisions/e3-choices.md`, „Tooltip od nowa”).
- Tekst tooltipa w pasku ucięty pionową kreską, gdy dymek zmienia szerokość, przy szybkim ruchu dymek pusty, a na końcu przejścia tekst podskakuje o 1 px → nowy, dłuższy tekst miał od razu pełną szerokość w węższym dymku; każda zmiana celu zaczynała nową etykietę od krycia 0; spoczynek bez transformacji przyciąga tekst do piksela inaczej niż ruch ze `scale`. Tekst ściska się do bieżącej szerokości dymka (`--ts-i-tip-squish`, szerokość mierzona bez bieżącej skali), etykieta, która jeszcze wjeżdża, dostaje nowy tekst w miejscu, spoczynek ma skalę `--ts-motion-press-rest` → strażnik `tooltip.spec.ts` („keeps the text of a sliding list tooltip inside the bubble and readable in every frame…”), decyzja w `docs/decisions/e3-choices.md` („Tekst tooltipa na liście z przesuwaniem”).
- Wjazd tooltipa nie jechał (dymek tylko się wygaszał) → pomiar stylu przed ustawieniem `data-side` dawał stan zamknięty bez przesunięcia, a jego przejście zjadało wjazd; przy pierwszym ustawieniu (`data-snap`) przejście ma tylko krycie, a `data-side` stoi przed pomiarem → strażnik `tooltip.spec.ts`. Ta sama pułapka: `transform: none` w regule `[data-open]` zjadało `scale` przy budowaniu CSS; nie mieszaj `transform` z osobnymi właściwościami ruchu w jednej regule.
- Karta z polami w wąskim dialogu rozpycha się (kolumny 256 + 256 px w karcie 243 px) → nagłówek rozciągnięty na obie kolumny siatki wnosi jako minimum min-content swojej akcji (pełna etykieta przycisku); `min-inline-size: 0` slotu `header` w przepisie `surface` → strażnik `edges.spec.ts` („keeps every popup with long strings in the window…” przy oknie 320 px).
- Dwa przyciski z etykietą wystają z ramki 120 px albo z wąskiej karty → najmniejsza szerokość 2,5 × wysokość jest twarda (jak v2), a rząd akcji się nie zawijał; minimum tylko dla samodzielnego przycisku (bez segmentów `track` i `joined`), `flex-wrap: wrap` rzędu `actions` przepisu `surface` → strażniki `edges.spec.ts` (sekcja Overflow) i `button.spec.ts` („keeps a lone button with a label at least 2.5 heights wide…”).
- Wartość pola ucięta w pół znaku bez wielokropka („https://manc”) → natywny `<input>` przewija tekst; `text-overflow: ellipsis` slotu `input` przepisu `control` → strażnik `edges.spec.ts` (sekcja Overflow).
- Akcje karty dopasowanej do treści wystają o kilka px, gdy przycisk ma `min-width: min(…, 100%)` → procent w minimum liczy się jako 0 przy liczeniu szerokości rodzica, a przy układzie jako 100 %; najmniejsza szerokość przycisku z etykietą to sama długość (`--ts-size-label-min`) → strażnik `symmetry.spec.ts` („pads a card, a popover and a dialog composed of their parts alone…”).
- Część komponentu złożonego w złej kolejności przechodziła bez błędu przy otwarciu dialogu → popup montuje się w portalu bez ponownego renderu gospodarza, więc `useLayoutEffect` gospodarza nie widział elementu; `useSlotOrder` sprawdza też w ref przy podpięciu → strażnik `edges.spec.ts` („blocks a part out of the slot order…”).
- `FieldError` bez dzieci pokazuje pusty komunikat zamiast komunikatu przeglądarki → Base UI łączy propsy tak, że jawne `children: undefined` nadpisuje jego komunikat; część przekazuje `children` tylko wtedy, gdy konsument je podał → strażnik `field.spec.ts` („shows the error…”).
- Popup przy kliknięciu triggera skacze, mruga i zmienia szerokość → `scale` wciśnięcia na kotwicy zmieniał jej prostokąt (Floating UI liczy z niego pozycję i `--anchor-width`), a nawet niewidoczna skala spoczynku 0,99999 na kotwicy przesuwa popup o 1 piksel urządzenia przez zaokrąglenie Floating UI; kotwica stoi, skalują się jej sloty i płytka `::before` → strażnik `button.spec.ts` („presses the whole control of every button and only the parts and the plate of an anchor…”, „keeps a popup and its trigger still…”) i `interaction.spec.ts`.
- Tekst i ikony przycisku przeskakują o ułamek piksela (do 1 px przy DSF 1) na starcie i końcu wciśnięcia → Chromium odrzuca ułamek przesunięcia malowania przy każdej transformacji innej niż przesunięcie i przy warstwie, więc spoczynek bez transformacji rysuje się inaczej niż ruch; spoczynkowe `scale: var(--ts-motion-press-rest)` (0,99999) w grupie „skala” i na częściach kotwicy, warstwa tylko przy `[data-pressing]` → strażnik `jump.spec.ts`.
- Szew grupy `joined` z półprzezroczystą podstawą („Pages”, soft) jaśniejszy o 0,03–0,09 przy każdym DPR po dodaniu spoczynkowej skali → każdy segment z własną transformacją gubi ułamek położenia osobno, więc między segmentami zostaje szczelina do 1 px CSS; spoczynkowa skala na całej grupie `joined` bez kotwicy wśród segmentów (`surface`) → strażnik `button-group.spec.ts` („paints the seams between the segments…”).
- Otwarcie menu laguje w zwykłej przeglądarce → modalne menu Base UI daje `overflow: hidden` na `<body>` (przy klasycznym pasku Windows przebudowa całej strony) i `data-base-ui-inert` na rodzeństwie (przeliczenie stylu ok. 520 elementów w jednej klatce); `Menu` ma domyślnie `modal={false}` → strażnik `menu.spec.ts` („opens a menu without locking the scroll…”). Inert zostaje (Base UI), liczby w `docs/decisions/e3-budgets.md`.
- Menu ma za duży padding (9,5 px przy `full`) → dodatek ¼ promienia trafiał do powierzchni z wierszami, które same są koncentryczne i mają padding; wejście `data-content="controls"` silnika `shape` daje sam odstęp i obrys → strażnik `symmetry.spec.ts` (oczekiwany odstęp zależny od rodzaju treści).
- Przy `corners="full"` przyciski i pola w karcie nie są kapsułą (12,7 px zamiast 14 px) → promień kontrolki `min(własny, inner)` w powierzchni; przy kapsule `max(…, kapsuła)` → strażnik `symmetry.spec.ts` („rounds every one-line control… into a capsule”).
- Wartość opakowania kontrolek z gęstości zamiast z rozmiaru: tor ToggleGroup i ButtonGroup stały 5 px przy każdym rozmiarze i rósł z gęstością (38 → 46 px), menu przy `xs` miało róg 28,8 px wokół wierszy 16 px, a przy `xl` padding 4 px przy wierszach 36 px → odstęp `track`, `joined` i `data-content="controls"` to `--ts-size-wrap` (silnik `size`, wysokość / 8) + obrys, promień = promień kontrolki + odstęp (silnik `shape`); te same opakowania wychodzą z łańcucha powierzchni z tekstem (`:not([data-content='controls'])`) → strażnik `scale.spec.ts` (tabela rozmiarów ściśle rośnie, gęstość skrajna nie zmienia kontrolek ani opakowań, wiersz menu koncentryczny z menu).
- Koncentryczność bez progu: kontrolki w karcie i dialogu przy rogach `sm`/`md`/`lg` miały 4 / 4 / 7,3 px zamiast własnych 6,4 / 9,6 / 12,6 px, bo przy odstępie 20 px wzór „promień − odstęp” schodzi do minimum → od `--ts-shape-inset` ≥ 16 px (`--_ts-shape-loose-inset`, `sign()` w silniku `shape`) kontrolka, „×” i akcja nagłówka mają własny promień; koncentryczność tylko w ciasnych opakowaniach → strażnik `scale.spec.ts` (rogi `none`–`full`, oba `curve`) i `symmetry.spec.ts` (`expectCorner`).
- Wartość zależna od rozmiaru stała przy osi `size`: tooltip identyczny przy `xs` i `xl`, Kbd i Badge zawsze `xs`/`sm`, „×” rósł z osią ponad tytuł, odstęp ikona–tekst `xs` = `sm` → tooltip ma geometrię kontrolki (wariant `tooltip` przepisu `surface`), Kbd i Badge bez propa nie ustawiają `data-size`, „×” i tytuł mają `TITLE_LINE_SIZE`, `--ts-size-gap` ze wzoru → strażnik `scale.spec.ts`. W laboratorium klawisz i licznik w tekście, wierszu menu albo tooltipie mają jawny `size`.
- Hover `soft` i triggera w jasnym trybie ledwo widoczny (0,024 jasności OKLab przy 4 → 7 %) → drabinka jasna 4 / 8 / 12 % (krok 4 jak w ciemnej) → strażnik `scale.spec.ts` (≥ 0,028 w obu trybach).
- Między segmentami grupy `joined` jasna albo ciemna linia, tylko przy ułamkowym DPR (1,25 / 1,5) → krawędzie dwóch sąsiednich płytek wypadają w jednym pikselu urządzenia i każda kryje go częściowo, więc prześwituje strona; cień płytki segmentu o obrys w stronę początku w kolorze podstawy (`--_shade` w regule `joined` przepisu `control`), nie `inset: 0` płytki (odkrywa ramkę) → strażnik `button-group.spec.ts` („paints the seams between the segments…” przy DPR 1,25 i 1,5).
