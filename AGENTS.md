# Tessera

System stylu i komponentów React (`@mattymroz/tessera`) dla aplikacji właściciela: konsument składa interfejs z części Tessery i nie pisze własnych stylów. Repo to bun workspace z jedną paczką i stroną dokumentacji, która jest zarazem laboratorium.

## Bramki jakości

```sh
bun run check          # typecheck (TS 7) → build (tsdown, potem next build) → eslint → bunx vitest run --maxWorkers=6 → Playwright laboratorium (test:browser)
bun run dev            # tsdown --watch paczki i next dev laboratorium równolegle, jeden link
bun run perf           # build, potem T1–T5, N8 i S-A na /stress (Chromium, CPU 4x, mediana z 5, ok. 2,5 min); poza check i CI
bun run perf:save      # to samo i zapis apps/docs/perf/last.json jako nowego punktu odniesienia
SKIP=no-commit-to-branch prek run --all-files   # hooki commitów na całym drzewie (na main bez SKIP zawsze czerwone)
```

- IMPORTANT: testy tylko `bunx vitest run`, NIGDY `bun run test`.
- Playwright tylko headless i z jednym workerem; testy lekkie, komputer właściciela się zacina.
- Hook pre-push uruchamia te same pięć kroków co `bun run check`, w tej samej kolejności: build przed lintem, bo wtyczka ESLint konsumenta jest czytana z `dist`. Instalacja po klonie: `git config --local core.autocrlf false`, `prek install`, a w `apps/docs` `bunx playwright install chromium webkit` (bez przeglądarek `check` pada na ostatnim kroku; CI instaluje je sam).

## Twarde reguły

- IMPORTANT: commit i push tylko na wyraźne słowo właściciela. Subagenci nie wykonują żadnych komend git.
- `main` dostaje tylko squash merge PR (hook `no-commit-to-branch`). Praca na branchach w worktree `.worktrees/<nazwa>`. Tytuł PR = nagłówek commita, opis PR = streszczenie i blok `Validation:` (ustawienie repo: domyślna wiadomość squash = tytuł i opis PR).
- Commit: `type(scope): description`, scope obowiązkowy z zamkniętej listy `--scopes` w `.pre-commit-config.yaml`; pod nagłówkiem streszczenie i blok `Validation:` z kontrolami faktycznie uruchomionymi przez `mm-validate` (hook `commit-validation`; instalacja `uv tool install git+https://github.com/MattyMroz/agents@hooks-v1.1.0`). Format: `presets/hooks/references/commit-message.md` w repo MattyMroz/agents. Zero śladów AI w commitach i PR.
- Kod etapu nie powstaje bez kontraktu w `docs/plans/` zaakceptowanego przez właściciela.
- Status przed oceną właściciela na żywo, w kompozycji, to najwyżej „gotowe do oceny”.
- Zero legacy: bez warstw zgodności z v1/v2, aliasów starych nazw i słowa `legacy` w kodzie. Kod przenoszony z v2 przepisuj na model v3.
- Zero pustych folderów i pakietów „na zapas”: folder powstaje z pierwszym plikiem.
- IMPORTANT: zero komentarzy w kodzie (TS, TSX, CSS, skrypty, testy, fixture), także WHY; kod tłumaczy się nazwami stałych, funkcji i plików. Powód, którego nie da się wyrazić nazwą, trafia do `docs/` (decyzja, plan) albo do opisu commita.
- Kod, nazwy, git i tekst UI po angielsku; dokumenty w `docs/` i ten plik po polsku.
- Zależności tylko przez bun: `bun add` w katalogu członka workspace, wspólne wersje przez `catalog:` w korzeniowym `package.json`.
- YOU MUST edytować pliki tylko narzędziami Edit/Write. Nigdy PowerShell (`Set-Content`, `Out-File`) ani skrypty: PS 5.1 robi mojibake z polskich znaków. Pliki są UTF-8 + LF (`.gitattributes`).

## Model warstw

Trzy piętra: **silniki** → **przepisy** → **komponenty**; motyw to tylko zestaw wyborów silników. Warstwy w `packages/tessera/src/` powstają z pierwszym plikiem:

- `engines/<silnik>.css` (jeden plik na silnik; reguły i zmienne w `@layer theme`, a `@keyframes`, `@property` i `@font-face` na szczycie pliku poza warstwą, bo tak wymusza strażnik): wejścia (`data-*`, `--ts-in-<silnik>-*`) → wyjścia `--ts-<silnik>-<rola>`. Publiczne API to wyjścia silników i klucze rejestru wartości instancji `--ts-i-*`. Silnik deklaruje tylko własne wyjścia, wejścia i prywatne `--_ts-<silnik>-*` i czyta tylko silniki, od których zależy. Rejestr `@property --ts-i-*` (`inherits: false`) żyje tylko w `size.css`, a jego klucze to dokładnie `INSTANCE_KEYS` z `lib/instance.ts`. `@keyframes` są tylko w `motion.css`: wyłącznie `ts-spin`, `ts-sweep`, `ts-pulse`, z samymi `transform`/`translate`/`rotate`/`scale`/`opacity`. Wyjątek: `color.css` jest generowany (`bun run generate:colors` w paczce, dane w `scripts/palette.ts`), nie edytuj go ręcznie.
- `recipes/<przepis>.css` (w `@layer components`, sześć przepisów: `control`, `surface`, `row`, `indicator`, `focus`, `text`): wartości wyłącznie z wyjść silników, kluczy rejestru `--ts-i-*`, własnych `--_*`, zmiennych dostawcy z listy `VENDOR_VARIABLES` i liczb `0`, `1`, `-1`, `100%`; funkcje tylko `calc`, `min`, `max`, `clamp` i `color-mix(in oklab, …)`; nigdy inne liczby ani kolory, prefiksy producenta ani arytmetyka na `--_*` zbudowanej z literału. At-rule tylko `@media (hover: hover)`, `@media (forced-colors: active)` (słowa kolorów systemowych, np. `Highlight`, `ButtonText`, wyłącznie w tym bloku), `@container` z progiem z `CONTAINER_WIDTHS` i `@supports (overflow-clip-margin: border-box)` tylko w `control` i tylko z `overflow` i `overflow-clip-margin` (przycięcie pętli do obrysu, powód w `docs/structure.md`; blok bez tych właściwości oblewa); `@starting-style` zabroniony, także dla toastu: jego wejście (E3) idzie przez atrybut `data-starting-style` Base UI i zwykłe `transition`. Ton (`data-tone`) jest osią obok wariantu, nie nowym wariantem; powierzchnia z tonem bez obrysu. Selektor celuje w element przepisu, jego `[data-slot]` albo pseudo-element (bez `~`, `+`, `:root`, `html`, `body`); wyjątki z powodem w `docs/structure.md`.
- `components/<rodzina>/<nazwa>.tsx` (+ opcjonalnie `<nazwa>.css` importowany tylko z `tessera.css`): CSS tylko z rozmieszczeniem części (`display`, `gap`, wyrównania, `flex*`, `order`, kolumny i wiersze siatki) i wartościami z tokenów, tylko w zakresie `[data-component='<nazwa>']` i jego części; jedyne at-rule to `@container` z progiem z `CONTAINER_WIDTHS` (`test/guards/css-layers.ts`) i samymi właściwościami układu. Rozmiar, pozycja, kolor, promień, cień, ruch, liczby poza `-1`/`0`/`1` i własny `:focus-visible` należą do przepisów i silników.
- TSX komponentu: bez `className` i budowania klas; `style` tylko jako obiekt literalny z kluczami rejestru `--ts-i-*` (wartość instancji, np. postęp); wartość z pomiaru DOM zapisuje `writeInstance` tylko w plikach z listy pomiaru (Q7: `lib/indicator.ts`, `lib/motion.ts`, `lib/popup-flight.ts`, `lib/title-when-cut.ts`; pomiar to też odczyt `scrollWidth`, `clientWidth`, `scrollHeight`, `clientHeight`, `scrollTop`, `scrollLeft`). Bez literałów liczbowych poza `0`, `1`, `-1` (także w stałych; czasy zachowania to nazwane stałe w `lib/`) i bez atrybutów wyglądu SVG (`strokeWidth` i inne spoza białej listy w `docs/structure.md`). Glify komponentów i ikony laboratorium pochodzą z lucide: domyślny import modułu jednej ikony (`import Check from 'lucide-react/icons/check'`, w paczce pilnuje `test/package/package.test.ts`), bez propsów wyglądu; rozmiar daje slot, grubość kreski przepis (`docs/decisions/e3-icons.md`). Pozycje typów (`level: 1 | 2 | 3 | 4`) są dozwolone.
- Komponent nie zawiera tekstu UI w żadnym języku: każda etykieta (np. `cancelLabel` w `confirm()`) to wymagany prop bez wartości domyślnej; `onClick` tylko na elemencie interaktywnym albo kontenerze widżetu złożonego z rolą (`radiogroup`). Pilnuje `test/guards/component-source.ts` (wywołany z `contracts.test.ts`).
- Zmiana wyglądu jednego elementu = wariant przepisu, nie token komponentu. Poprawki wyglądu idą do silników i przepisów, nie do komponentów.
- Pilnuje tego `packages/tessera/test/guards/css-layers.ts` (biała lista per warstwa, fixture `good/` i `bad/`), `contracts.test.ts` i blok `tessera/components` w `eslint.config.js` (lokalna reguła repo `tessera-source/component-appearance` z `test/guards/component-appearance.ts`, ładowana ze źródła, poza publiczną wtyczką); propsy elementu i części Base UI idą przez jeden typ `Unstyled` (`lib/unstyled.ts`), który zdejmuje `className`, `style` i `render`. Nowa reguła dostaje strażnika od razu: biała lista plus jawne wyjątki z powodem, nigdy kopia listy tokenów.

## Wydajność i ruch

Priorytet nr 1 to wydajność. Pełna lista wymagań i budżetów: `docs/specification.md`, sekcja „Wymagania jakościowe”.

- Ruch tylko `transform`/`translate`/`scale`/`rotate`/`opacity`. Każdy inny przypadek to nazwany wyjątek z powodem w jednym pliku. Zmiana rozmiaru dzieje się w jednej klatce, nigdy w ruchu.
- IMPORTANT (reguła właściciela, błąd powtarzany wielokrotnie): nigdy nie transformuj (`scale`, `translate`, `rotate`) elementu, do którego przypięty jest inny element — kotwicy popupu, menu, tooltipa, podmenu, pigułki — ani przodka takiej kotwicy czy przypiętego elementu. Wciśnięcie (`scale`) i inny ruch idą na osobną, wewnętrzną warstwę: w `control` to płytka `::before` (tło, obrys i cień wariantu), a pudełko kontrolki i jej treść stoją, więc popup nie skacze, nie mruga i nie skaluje się razem z triggerem. Strażniki w `button.spec.ts`: „presses only the plate of a control…” (`data-pressing` na każdej kontrolce trzech stron, żaden element nie ma `scale` ani `transform`) i „keeps a popup and its trigger still…” (menu, menu szerokości triggera, popover, tooltip, podmenu: prostokąty co 8 ms przed, w trakcie i po wciśnięciu).
- Nie udawaj zmiany rozmiaru kopiami DOM ani kawałkami wskaźnika lub popupu: ta droga została sprawdzona i odrzucona.
- Zero runtime CSS-in-JS. Wariant i motyw to atrybuty `data-*` + CSS, nie kontekst React.
- Kształt i rozmiar nie przechodzą przez JS (bez `ResizeObserver` + `getComputedStyle` + `setProperty`); pomiar DOM tylko tam, gdzie wymaga go zachowanie, w plikach z nazwanej listy.

## Pułapki

- Testy `test/package/` i laboratorium czytają `packages/tessera/dist/`: bez świeżego `bun run build` oblewają albo widzą stary build. `bun run check` buduje przed testami. Na świeżym klonie przed pierwszym `bun run dev` zrób `bun run build`, bo `--parallel` nie czeka, aż tsdown skończy.
- Typecheck idzie przez TypeScript 7 (`typescript7` = `npm:typescript@^7`, skrypt `typecheck` każdego członka). TypeScript 6 zostaje tylko jako peer `typescript-eslint`; nie zamieniaj ich.
- `git worktree remove` (z `--force` i bez) wchodzi na Windows w junctiony i kasuje ich cel. Junctiony robią `link:` u konsumenta (paczka Tessery w worktree MangaShift) i linki skilli. Przed usunięciem worktree albo katalogu najpierw zdejmij linki (`rmdir` na junction), potem `git worktree remove` bez `--force`. Globalny `guard.sh` odmawia usunięcia, dopóki linki istnieją.
- W worktree nie synchronizuj skilli: `@core` jest globalny.
- `mm-validate run "<kontrola>" -- <komenda>` uruchamia komendę bez powłoki Git Bash: `bash -c …` trafia na Windows w `bash` z WSL (`execvpe(/bin/bash) failed`), a `bunx playwright` z korzenia repo bierze paczkę bez komendy `test`; oba zapisują `failed`. Hook `mdformat` przy commicie przepisuje Markdown, więc przed `mm-validate` puść `prek run` po `git add -A`, aż drzewo przestanie się zmieniać; zapis kontroli dotyczy dokładnego drzewa.
