# R3: wydajność Tessery v3 (reguły, budżety, kontrola)

Stan na 2026-10-30. Researcher, tylko odczyt. Źródła sprawdzane 2026-10-30.

Oznaczenia w tabelach: **F** fakt ze źródła, **W** wniosek z kilku faktów, **O** opinia autora źródła, **R** rekomendacja tego raportu, **N** niewiadoma.

### 2.3 `@layer` i `color-mix()`

| Mechanizm     | Co wiadomo                                                                                                                                                                                                                                                        | Typ   |
| ------------- | ----------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- | ----- |
| `@layer`      | Warstwy zmieniają kolejność w kaskadzie, nie dopasowanie selektorów ([Chrome blog](https://developer.chrome.com/blog/cascade-layers)). Nie znalazłem pomiaru kosztu warstw.                                                                                       | F + N |
| `color-mix()` | Rozwiązywany w computed-value time, jak `calc()`. Jedyne twierdzenie o koszcie („pomijalny, potrzeba tysięcy deklaracji”) pochodzi z bloga bez pomiaru ([OpenReplay](https://blog.openreplay.com/de/css-relative-farbsyntax/)). v2 ma 374 wywołania `color-mix(`. | F + O |
| **W**         | Oba mechanizmy kosztują przy recalc, nie przy kompozycji. Ich koszt rośnie z liczbą elementów restylowanych naraz, więc ograniczenie W2 (brak zapisów wysoko w drzewie) chroni też przed nimi. Pomiar v2 vs v3 na tej samej scenie rozstrzygnie resztę.           | W     |
