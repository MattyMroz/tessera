### 1.3 Rozmiar: własny pomiar (F)

Metoda: `bun build --minify --target browser`, `process.env.NODE_ENV="production"`, `react`/`react-dom` jako external, wejście `export * from '<prymityw>'`, wynik w gzip -9. Bun 1.4.3. Pakiety z lokalnego store: Radix w wersjach dla `radix-ui` 1.6.7, Base UI 1.8.0. Każdy prymityw zmierzono osobno, więc wspólny kod (Floating UI, warstwy) liczy się w każdym wierszu, a suma zawyża koszt całej aplikacji. React Aria, Ark, Ariakit i Headless UI nie są zainstalowane lokalnie, więc ich nie zmierzono (**?**).

- **W:** na desktopie (Tauri, pliki lokalne) rozmiar paczki ma mały wpływ na wydajność; liczy się koszt montowania, renderów i przebiegów stylu. Base UI deklaruje tu postęp: zamykane popupy montują się do 50% szybciej, odmontowują do 85% szybciej (1.5.0), triggery szybciej (1.8.0), a duże listy szybciej (1.9.0) ([releases](https://base-ui.com/react/overview/releases.md)). Te liczby pochodzą od autora i nie zostały przeze mnie odtworzone.

## 6. Rekomendacja per prymityw

Kryteria (z kolejnością ważności podaną w zleceniu):

1. **Wydajność:** brak przebiegów po całej stronie (`body` pointer-events, `aria-hidden` na wszystkim, reguła `*`), mało montowanych Rootów, animacje na compositorze.
2. **Poprawność zachowania:** klawiatura, focus, a11y i pozycjonowanie bez łatania prywatnych detali (`onPlaced`, `-200%`, `data-radix-*`).
3. **Zgodność z ruchem Tessery:** wyjście przez przejścia CSS, przelot popupu między triggerami, wskaźnik podświetlenia.
4. **Koszt utrzymania:** im mniej własnego kodu a11y, tym lepiej, o ile nie trzeba go obchodzić.

Kompromis ogólny: Base UI waży więcej (§1.3), ale usuwa największe obejścia v2 (§3 #1-11, 13, 18, 30). Własna implementacja daje pełną kontrolę, ale klawiaturę, focus i a11y trzeba wtedy samodzielnie testować na WebView2 i WebKit.

### Disconfirmation pass (co mogłoby obalić rekomendację Base UI)

| Ryzyko                                                                                    | Stan sprawdzenia                                                                                                                                                 |
| ----------------------------------------------------------------------------------------- | ---------------------------------------------------------------------------------------------------------------------------------------------------------------- |
| Base UI jest cięższe w runtime, nie tylko w paczce                                        | **?** nie zmierzono; potrzebny bench montażu 200 tooltipów i menu na WebView2 (v2 ma `bun run perf`)                                                             |
| Radix po ożywieniu naprawi to samo                                                        | częściowo: łata błędy (#3445, #4160), ale nie zmienia architektury (`body` pointer-events, Presence tylko na `animationend`, brak Combobox i wspólnego tooltipa) |
| React Aria lepsze w a11y                                                                  | **O:** prawdopodobne, ale API i własne pozycjonowanie oznaczają większy przepis Tessery; nie zmierzono rozmiaru                                                  |
| Przelot tooltipa w Base UI animuje `width/height`, a Tessera chce tylko transform/opacity | **?** dokumentacja mówi o przejściu offsetów i wymiarów Popupu; trzeba sprawdzić, czy da się je wyłączyć (`data-instant`) i animować po swojemu                  |

| #   | Pytanie                                                                                                   | Dlaczego ważne                                                               |
| --- | --------------------------------------------------------------------------------------------------------- | ---------------------------------------------------------------------------- |

| 4   | Czy panele desktopu mają przeżywać zmianę zakładki i przeniesienie (`always` jak w Dockview)?             | koszt pamięci vs utrata stanu (scroll, zaznaczenie)                          |

| 6   | Czy `cmdk` zostaje dla palety komend po przejściu Combobox na Base UI?                                    | jedna czy dwie biblioteki list                                               |
