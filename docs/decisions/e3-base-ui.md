# Próby N7 dostawcy Base UI w E3

Wyniki prób N7 z kroku R1 każdej rundy (plan E3, „Przebieg rundy”). Wersja dostawcy: `@base-ui/react` 1.9.0. Dowód: testy Playwright (Chromium 1.64 i WebKit Playwrighta) albo odczyt kodu dostawcy; przy każdym wyniku podane, który.

## Runda C: Field, Input, Textarea, Alert Dialog

### Field (D59)

| Pytanie                              | Wynik                                                                                                                                                                                                                                                                                                            | Dowód                                                                                                                                                                              |
| ------------------------------------ | ---------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- | ---------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- |
| DOM                                  | `Field.Root` = `<div>`, `Field.Label` = `<label>`, `Field.Description` = `<p>`, `Field.Error` = `<div>` tylko w stanie błędu (bez błędu brak węzła)                                                                                                                                                              | sonda Playwright na `/components`                                                                                                                                                  |
| Etykieta ↔ Input                     | `Field.Control` rejestruje się w polu: `label[for]` = `id` pola, pole ma `aria-labelledby` = `id` etykiety i `aria-describedby` = `id` opisu (+ `id` błędu, gdy jest)                                                                                                                                            | sonda; `field.spec.ts` „labels the input…”                                                                                                                                         |
| Etykieta ↔ Textarea                  | to samo przez `Field.Control render={<textarea />}`                                                                                                                                                                                                                                                              | `textarea.spec.ts` „takes the label of its field…”                                                                                                                                 |
| Etykieta ↔ Select, Checkbox, Switch  | `SelectTrigger`, `CheckboxRoot`, `SwitchRoot` wołają `useLabelableId`, więc rejestrują się w tym samym kontekście bez kodu Tessery                                                                                                                                                                               | odczyt kodu (`select/trigger/SelectTrigger.js:83`, `checkbox/root/CheckboxRoot.js:102`, `switch/root/SwitchRoot.js:82`); próba w przeglądarce w rundach D i E razem z komponentami |
| Kontrolka bez rejestracji (fallback) | `Field.Label` dostaje `for` z wygenerowanym `id`, któremu nie odpowiada żaden element, więc klik etykiety nic nie robi. Tessera: `FieldLabel` przy `label.control === null` fokusuje element o `id` z `for`, a gdy go nie ma, pierwszy fokusowalny element pola                                                  | sonda (`for="base-ui-…"`, `control` = `undefined`); `field.spec.ts` „focuses a control that a label cannot name…”                                                                  |
| `validationMode`                     | domyślne Base UI `onSubmit`; Tessera ustawia `onBlur`. Po wyjściu z pola `aria-invalid`, `data-invalid`, `FieldError` i obrys `:user-invalid` pojawiają się w tej samej chwili. Puste wymagane pole bez wpisywania nie jest błędne po wyjściu ani dla Base UI, ani dla `:user-invalid` (oba czekają na wysłanie) | `field.spec.ts` „shows the error, the invalid state…”, sonda `untouched null false`                                                                                                |
| `FieldError`                         | bez roli u dostawcy; Tessera dodaje `role="alert"`                                                                                                                                                                                                                                                               | `field.spec.ts`                                                                                                                                                                    |
| Wyłączenie                           | `Field disabled` wyłącza `Field.Control`; przygaszenie gospodarza z `:has(> [data-slot='input']:disabled)` w `control`                                                                                                                                                                                           | `field.spec.ts` „disables and dims…”                                                                                                                                               |

### Węzły B5

| Kontrolka                   | Węzły                                                                    | Limit spec B5 |
| --------------------------- | ------------------------------------------------------------------------ | ------------- |
| Input bez slotów            | 2 (`div` + `input`)                                                      | 2 + sloty     |
| Input z ikoną i przyciskiem | 4 (slot ikony = 1, slot z przyciskiem = 1, przycisk to treść konsumenta) | 2 + 2         |
| Textarea                    | 2 (`div` + `textarea`)                                                   | 2             |

Pomiar: `field.spec.ts` i `textarea.spec.ts` (ta sama funkcja liczenia co `budgets.spec.ts`). Field to układ, nie kontrolka: 3 węzły (`div`, `label`, `p`) + 1 w błędzie.

### Alert Dialog i `confirm` (D67)

| Pytanie              | Wynik                                                                                                                                                                                                                                  | Dowód                                                               |
| -------------------- | -------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- | ------------------------------------------------------------------- |
| Uchwyt               | `AlertDialog.createHandle()` i `openWithPayload(payload)` istnieją w 1.9.0 (`alert-dialog/handle.d.ts`, `dialog/store/DialogHandle.d.ts`); `Root` przyjmuje dzieci jako funkcję `({ payload })`                                        | odczyt typów; `alert-dialog.spec.ts`                                |
| Host nieobecny       | `openWithPayload` bez zamontowanego `Root` nic nie robi (ostrzeżenie w dev), `isOpen` = `false`, więc `confirm()` rozwiązuje `false` od razu                                                                                           | odczyt kodu `DialogHandle.js`                                       |
| Treść przy zamykaniu | `payload` nie jest czyszczony po zamknięciu (czyszczą go tylko tooltip i preview card), więc treść okna zostaje do odmontowania                                                                                                        | odczyt kodu; `alert-dialog.spec.ts` „keeps the text and the state…” |
| Blokada zamknięcia   | `onOpenChange` dostaje `eventDetails.cancel()`; po `cancel()` dostawca nie zmienia stanu (`popupStoreUtils.js:200`). W trakcie `onConfirm` Tessera anuluje każde zamknięcie poza `imperative-action` (własne zamknięcie po sukcesie)   | `alert-dialog.spec.ts` „keeps the window open with a busy action…”  |
| Pierwszy fokus       | pierwszy element z kolejności Tab, więc „Cancel” stoi pierwszy w DOM                                                                                                                                                                   | `alert-dialog.spec.ts` „puts Cancel first…”                         |
| Klik w tło           | `role="alertdialog"`, `disablePointerDismissal` wymuszone przez dostawcę                                                                                                                                                               | `alert-dialog.spec.ts` „stays open after a click on the backdrop”   |
| Części               | `AlertDialog.Popup`, `Title`, `Description`, `Close` to części Dialogu (`alert-dialog/index.parts.d.ts`), więc okna niestandardowe używają `DialogPopup`, `DialogTitle`, `DialogDescription`, `DialogActions`, `DialogClose` z Tessery | odczyt typów; `alert-dialog.spec.ts` „opens a custom alert dialog…” |
