## Decyzje właściciela (04.11)

- Trigger = przycisk Tessery (`soft`/`outline`) z szewronem, nie pole.
- Lista ma tryby: na triggerze (wybrana opcja na wartości, tekst nie przeskakuje), nad, pod. Tryb na triggerze to główne zadanie.
- Znaczniki wiersza są globalne dla Menu, menu kontekstowego, paska i Selecta: ptaszek = zaznaczone, kropka = jedno z wielu (zwykła kropka jak w MangaShift desktop, NIE pudełko radia), szewron = podlista. Co stoi z przodu, a co z tyłu, ustali właściciel; mockup ma oba (`markSide`).
- Nie przenosić kodu z MangaShift; MangaShift tylko jako wzór wyglądu.
- Zamiana wartości po wyborze jak w referencji z X (stary tekst w górę i gaśnie, nowy od dołu); warianty A (przesuw) i B (przesuw + rozmycie) do wyboru.
- Szewron bez animacji (animacja `scale` z odbiciem odrzucona: „dziwna animacja”).

## Zweryfikowane fakty

- Tryb na triggerze: tekst opcji = tekst wartości w układzie strony, 0,000 px poziomo i pionowo, rozmiary xs–xl, DSF 1 / 1,25 / 1,5, lupa 1× / 2× / 4×, także po zmianie lupy przy otwartej wcześniej liście i przy ponownym otwieraniu (skrypt w scratchpadzie, pomiar `Range.getBoundingClientRect`). Sam Base UI chybia o 1–1,3 px (sekcja 1b).
- Piksele (zrzuty przed i po otwarciu kliknięciem, DSF 1–2): oba teksty z tym samym wygładzaniem LCD i w tym samym miejscu; środek ciężkości różni się o ≤ 0,04 px w pionie (sm–xl), poziomo 0,05–0,4 px z powodu innego tła pod tekstem (płytka przycisku kontra lista), nie położenia.
- Przyczyny przeskoku, usunięte w `alignText`: (1) Base UI porównuje pudełka różnego rodzaju (span wartości kontra przycięta etykieta wiersza); (2) lista `position: fixed` dostaje warstwę kompozytora (`Overlap`) i szare wygładzanie zamiast LCD; (3) lista z wysokością przyciętą o ułamek piksela jest przewijalna (`OverflowScrolling`), więc też dostaje warstwę. Naprawa: po ustawieniu przez Base UI pozycjoner przechodzi na `position: absolute` we współrzędnych dokumentu, lista bez przewijania dostaje naturalną wysokość i `overflow: visible`, a tekst jest domykany pomiarem w trzech przejściach; uruchamia to `MutationObserver` na `style` pozycjonera i `data-open` popupu (komponent nie renderuje się przy ponownym otwarciu).
- Lupa laboratorium robiła `zoom` tylko na `#lab-main`, więc żaden popup (Menu też) się nie skalował; teraz `zoom` na `<html>`.
- Domyślny znak Base UI `ItemIndicator` to tekst „✔️”; bez jawnego `children` trafia do środka znacznika.

## Ślepe uliczki

- Wyśrodkowanie wybranego wiersza na przycisku: lista szersza niż przycisk (najdłuższa opcja), tekst ucieka o 11–15 px. Odrzucone.
- `will-change` na etykiecie triggera, żeby oba teksty były szare: bez efektu. Odrzucone.
- Kropka jako pudełko radia z przepisu `control`: odrzucone przez właściciela.

## Otwarte (do decyzji albo pracy)

- Znacznik z przodu czy z tyłu w Selecie (domyślnie w mockupie: z tyłu, w miejscu szewronu, jak `MENU_PICK_ROW` w MangaShift; w Menu z przodu).
- Zamiana A czy B; B używa `filter: blur` = nazwany wyjątek od „ruch tylko transform/opacity”, wymaga śladu Chromium (nie zmierzony).
- Długa lista (przewijana): wciąż `fixed` i warstwa, czyli możliwy przeskok wygładzania; nie sprawdzone.
- Szerokość popupu przy lupie 2×/4× jest dwa razy za duża (`--anchor-width` Floating UI w pikselach ekranu przy CSS `zoom`); prawdziwe powiększenie przeglądarki tego nie ma.
- Mockup łamie strażników (stringi z liczbami w klatkach WAAPI, pomiar DOM w `select.tsx` poza listą Q7, style inline); `bun run check` nieuruchomiony.
